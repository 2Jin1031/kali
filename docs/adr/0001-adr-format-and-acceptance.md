# 0001. ADR 형식과 수락 규칙

상태: 수락됨
날짜: 2026-10-13

## 상황

AI(Claude Code)가 밤에 혼자 작업한다. 설계 선택지가 갈릴 때 AI가 고르면 아침에 되돌리기 어렵다. 선택지를 정리하는 일과 고르는 일을 나눠야 하고, 고른 결과가 저장소에 남아야 AI가 다음 작업에서 따른다.

## 선택지

- (가) 확정된 결정만 저장소 `docs/adr/`에, 계획·브레인스토밍은 저장소 밖(옵시디언)
- (나) 계획 문서까지 전부 저장소에
- (다) 전부 저장소 밖

| 기준 | (가) | (나) | (다) |
|---|---|---|---|
| AI가 따라야 할 결정을 바로 찾음 | ○ | △ 확정·미확정이 섞임 | ✕ |
| 공개 저장소에 정리 안 된 생각이 노출 | 없음 | 있음 | 없음 |
| 면접관이 결정 근거를 봄 | ○ | ○ | ✕ |

## 결정

(가). 형식은 **상황 / 선택지 2~3개 + 비교표 / 결정 / 결과 / 재검토 조건**.

- AI는 선택지를 정리해 "상태: 제안"으로만 올린다 (`/adr`). 수락은 사람만 한다
- "상태: 수락됨" ADR은 수정하지 않는다. AI가 반대하면 새 ADR을 제안한다

## 결과

- 수락된 ADR 수정은 CI 가드가 실패시킨다 (사람이 `사람-확인` 라벨로 인정하면 통과)
- 결정이 바뀌어도 옛 ADR이 남아 바뀐 이유를 추적할 수 있다

## 재검토 조건

- ADR이 너무 많아져 AI가 관련 ADR을 못 찾을 때 (목록·분류 방식 재검토)
