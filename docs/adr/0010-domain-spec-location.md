# 0010. 도메인 스펙 문서의 위치와 보호 방식

상태: 수락됨
날짜: 2026-10-14
0001 보완 (0001은 그대로 두고 확정된 결정을 두는 곳에 `docs/spec/`을 더한다)

## 상황

다음 단계부터 엔티티·스키마와 기능을 AI가 사람 없이(밤에) 만든다. 그때 물어볼 사람 없이 따를 기준이 도메인 스펙이다. 스펙에는 나중에 바꾸면 데이터 마이그레이션이 필요한 것(용어, 원본 위치, 유스케이스, 상태 변화, 규칙, 이벤트 이름)만 둔다.

맞춰야 할 두 규칙:
- 0001, `AGENTS.md`: 계획은 저장소 밖에 두고, 확정된 결정만 `docs/adr/`에 둔다
- 0002 권한 세 칸: 수락된 ADR 수정은 금지, 스펙에 없는 도메인 규칙이 필요하면 "물어보고". 작업 방식 원칙은 "스펙 문서를 마음대로 수정"을 금지 칸에 둔다

스펙은 계획이 아니라 확정된 결정의 묶음이다. 그런데 ADR처럼 결정 하나씩이 아니라, 지금 유효한 규칙 전체를 한 번에 읽혀야 한다.

## 선택지

- (가) `docs/spec/`에 스펙 문서를 두고 보호 경로에 추가한다. AI는 고치지 못하고, 바꿀 내용은 PR "내가 결정할 것"에 적는다. 사람이 고친 PR은 `사람-확인` 라벨로 통과시킨다
- (나) `docs/spec/`에 두되 보호하지 않는다. AI도 고칠 수 있고, PR 리뷰에서 사람이 본다
- (다) 스펙 문서를 따로 두지 않고 결정마다 ADR을 쓴다. 수락된 ADR은 이미 보호된다

| 기준 | (가) 스펙 + 보호 | (나) 스펙, 보호 없음 | (다) ADR만 |
|---|---|---|---|
| AI가 밤에 지금 유효한 규칙을 한 곳에서 읽음 | ○ 문서 하나 | ○ 문서 하나 | △ ADR 여러 장을 읽고 대체 관계를 따라가야 함 |
| AI가 스펙을 조용히 바꾸는 것을 막음 (금지 칸) | ○ 권한 차단 + CI 가드 | ✕ 사람이 diff에서 놓치면 그대로 들어감 | ○ 수락된 ADR은 수정 금지 |
| 초기에 스펙을 자주 고칠 때 비용 | △ 고칠 때마다 라벨 | ○ 낮음 | ✕ 고칠 때마다 새 ADR + 대체 표시 |
| 0001 "확정된 결정만 저장소에"와 맞음 | ○ 결정만 둠 (0001 보완) | ○ | ○ |
| 나중에 바꾸는 비용 | 낮음 (보호 경로 목록에서 빼면 (나)) | 낮음 | 중간 (흩어진 결정을 한 문서로 모아야 함) |

추천: (가). 밤에 AI가 따를 기준이 한 문서에 모여 있으면서, AI가 그 기준을 스스로 바꾸지 못한다. 고칠 때마다 라벨을 다는 비용은 스펙이 데이터 마이그레이션 수준의 결정만 담아서 자주 생기지 않는다.

## 결정

(가). 도메인 스펙은 `docs/spec/`에 두고 보호 경로에 추가한다.

## 결과

- 스펙 문서: `docs/spec/domain.md`. 결정만 쓰고, 정하지 않은 것은 "미정"으로 둔다
- 스펙 문서는 이번 PR에서 처음 만든다. 보호 경로 반영은 별도 PR에서 한다:
  - `.github/scripts/guard.sh` 보호 경로에 `docs/spec/`
  - `.claude/settings.json` deny에 `Edit(/docs/spec/**)`
  - `AGENTS.md` 보호 경로 목록에 `docs/spec/`, "확정된 결정만 ADR로" 규칙에 스펙 추가
- 선택지 비교가 필요한 스펙 결정은 지금처럼 ADR로 쓰고, 스펙 문서에서 그 ADR을 링크한다
- 스펙에 없는 도메인 규칙이 필요하면 AI는 지금처럼 묻고(0002), 밤에는 PR "내가 결정할 것"에 적는다

## 재검토 조건

- 스펙 수정 PR이 한 달에 다섯 번 넘게 생겨 라벨 비용이 부담될 때
- 스펙 문서가 커져서 AI가 관련 부분을 못 찾을 때 (주제별 파일로 나누기)
